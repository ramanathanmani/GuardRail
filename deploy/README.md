# Deploying GuardRail (Phase 8)

These files are written in Phase 0 but not run until Phase 8. **Claude Code never runs any of
this against AWS or the Vobiz console** — the steps below are for you to run by hand.

## By hand, before running `setup_ec2.sh`

1. Launch a `t3.small` Ubuntu 22.04/24.04 instance in `ap-south-1`, allocate and attach an
   Elastic IP.
2. Security group: allow port 22 from your IP only, and 80 + 443 from anywhere.
3. Point a DNS name you own at the Elastic IP, or use `<ip-with-dashes>.sslip.io`.
4. Attach an IAM role to the instance with `s3:PutObject` on your audit bucket only.
5. Create the S3 bucket (public access blocked).

## On the instance

```bash
git clone <your repo> /tmp/guardrail-bootstrap   # or scp the repo over
REPO_URL=<your git remote> /tmp/guardrail-bootstrap/deploy/setup_ec2.sh
```

This installs Python 3.12, Node, and Caddy; clones the repo to `/opt/guardrail`; builds the
backend venv and the frontend; installs the `guardrail` systemd unit; and copies the Caddyfile
into place. It prints the remaining manual steps (copying secrets over, wiring Caddy's env file,
starting both services).

## Secrets

`backend/.env` and `deploy/caddy.env` are never committed and never generated by this script.
Copy them from your laptop with `scp` after `setup_ec2.sh` finishes:

```bash
scp backend/.env      <host>:/opt/guardrail/backend/.env
scp deploy/caddy.env  <host>:/opt/guardrail/deploy/caddy.env
```

## Vobiz console (by hand)

Set the Voice Application's Answer and Hangup URLs to
`https://<SITE_ADDRESS>/vobiz/answer?k=<VOBIZ_STREAM_SECRET>` and
`https://<SITE_ADDRESS>/vobiz/hangup?k=<VOBIZ_STREAM_SECRET>` (both POST), and attach the DID to
the application.

## Checking it worked

```bash
curl https://<SITE_ADDRESS>/health
```

Then open the dashboard in a browser, confirm basic auth prompts, and confirm `/ws/dashboard`
connects (browser dev tools, Network tab, WS). If it doesn't over basic auth, see the note in
`deploy/Caddyfile` about moving `/ws/*` into the unauthenticated block.

## Rolling out a change later

```bash
ssh <host>
cd /opt/guardrail && git pull
cd backend && ./.venv/bin/pip install -r requirements.txt
cd ../frontend && npm install && npm run build
sudo systemctl restart guardrail
sudo systemctl reload caddy
```
